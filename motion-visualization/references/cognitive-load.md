# 인지부하 규칙

읽는 사람이 **내용 말고 다른 일**(단위 바꾸기, 칸 안에서 두 대상 나누기, 앞 장면 기억하기, 색 뜻 다시 맞추기)에 머리를 쓰게 만들지 않는다.
`build.py`가 `인지부하:`로 시작하는 경고를 낸다. 경고는 조립을 막지 않지만, 보고 전에 고치거나 고치지 않은 이유를 보고에 적는다.

## content.json을 쓰기 전에 정할 것 (묻지 않고 정해서 meta에 적는다)

| meta | 뜻 | 예 |
|---|---|---|
| `goal` | 누가 읽고, 다 읽은 뒤 무엇을 정하거나 하는가. 한 문장 | "내 앱을 Netlify와 Vercel 중 어디에 올릴지 정한다" |
| `purpose` | `decide`(고르기) · `learn`(이해) · `do`(따라 하기) | 비교·선택 요청이면 `decide` |
| `sides` | 비교 대상 두 개. **앞이 왼쪽·청록(accent2), 뒤가 오른쪽·강조색(accent)** | `["Netlify", "Vercel"]` |
| `terms` | 여러 번 나와도 되는 고유명사(반복 경고에서 제외) | `["클로드 코드", "Pickle"]` |

요청 문맥으로 알 수 있으면 사용자에게 다시 묻지 않는다. `goal`은 보고에도 한 줄로 적는다.

## 규칙 7개

1. **답 먼저.** `purpose=decide`면 첫 장면은 `decide`(질문 2~4개로 길 나누기) 또는 `verdict`. 배경 설명은 뒤로.
2. **한 개념은 한 장면에서만 자세히.** 표지·결론에서 같은 설명을 되풀이하지 않는다. 표지 `lines`는 비우거나 서로 다른 말만.
3. **비교는 `compare` 표.** 행=기준, 열=대상. 한 칸에 "A는… · B는…"를 함께 쓰지 않는다. 더 나은 쪽은 4번째 값으로 표시(`"a"`/`"b"` 또는 이름).
4. **같은 대상 = 같은 자리 = 같은 색.** `sides[0]`은 모든 장면에서 왼쪽·먼저·청록(`tone: "a2"`), `sides[1]`은 오른쪽·나중·강조색(`tone: "a1"`). folders 태그 색을 "우세" 기준으로 칠하지 않는다.
5. **결론 숫자는 같은 잣대.** 단위가 다른 숫자(크레딧·GB·달러)를 나란히 두지 않는다. 비교할 수 없으면 숫자를 빼고 `compare` 행으로 옮긴다.
6. **미확인은 그 자리에.** 본문 문장 끝에 `<span class="unv">미확인</span>`. 마지막 `ledger`는 모아 보기로 유지.
7. **장면 수 예산.** 결정용 6섹션 이하(표지 포함 7장), 한 장면 블록 2개 안팎. FAQ가 본문을 되풀이하면 뺀다.

## 고쳐 쓰기 예 (Netlify vs Vercel, 2026-11-27)

| 전 | 후 |
|---|---|
| 결론 숫자 `300크레딧 · 100GB · $9 · $20` | `decide` 질문 3개(상업용? Next.js? 팀 2명+?) |
| 플랜 `dict`: "Netlify … · Vercel …" 한 칸 | `compare` 표, 왼쪽 Netlify·오른쪽 Vercel 고정 |
| 'Vercel 우세' 태그가 청록(= 다른 장면의 Netlify 색) | 유리한 칸만 그 대상의 색으로 칠함 |
| '크레딧 한 통 vs 항목별 한도'가 4장면 | 요금 구조 장면 한 곳 |
| 미확인 4건이 마지막 장에만 | 본문 해당 칸에 `미확인` 표시 |
| 장면 9장 | 7장 |
