# 실수 메모

- **긴 줄표(—) 쓰지 않기.** build.py가 경고한다. 쉼표·마침표·가운뎃점(·)으로 바꾼다.
- **template.html을 읽거나 고치지 않기.** 크고 토큰이 많이 든다. 모양을 바꾸려면 theme·accent·labels·블록 선택으로 해결한다. 새 블록이 꼭 필요할 때만 템플릿의 `B.<이름>` 함수와 CSS를 추가하고 content-format.md 표에 한 줄 더한다.
- **content.json 전체를 채팅에 다시 출력하지 않기.** 고칠 곳만 부분 수정하고 다시 build한다.
- **화면 확인은 check.py 한 번 + 캡처 2장.** 문제가 있을 때만 `--full` 전체 캡처를 본다. 브라우저로 섹션마다 캡처를 반복하지 않는다.
- **check.py가 SKIP이면** "화면 미확인"이라고 보고한다. 정적 점검만으로 화면 완료라고 하지 않는다.
- **원문 예시와 새 아이디어 구분.** cases의 `verified`로 라벨을 다르게 한다.
- **재구성 화면은 진짜 캡처처럼 보이지 않게** caption에 "다시 그린 화면"이라고 쓴다.
- **명령어 안내:** Windows PowerShell은 `&&` 대신 `;`. 사용자 계정 자리는 `<내계정>`처럼 바꿔 쓰게 한다.
- **실제 계정·주소·개인정보**는 본문 예시에서 빼고 출처(ledger)에만 둔다.
- **글꼴은 인터넷에서 불러온다.** 오프라인에서는 기본 글꼴로 보인다는 점을 보고에 남긴다.

## 설명 영상·넘겨 보기에서 겪은 것

- 넘겨 보기: 옆 장면이 화면에 반쯤 걸쳐 있으면 IntersectionObserver가 '보임'으로 판단해 떠오르기 효과가 다시 안 켜진다. 장면 전환 때 직접 켜는 방식(revealIn)을 유지한다.
- MP4 녹화: Playwright 내장 영상 녹화는 별도 ffmpeg 내려받기가 필요해 막힐 수 있다. `record.py`는 브라우저 화면 프레임(screencast)을 받아 시스템 ffmpeg로 묶는다.
- ffmpeg에 한글 경로를 넘기면 'Illegal byte sequence'가 날 수 있다. 영문 임시 경로로 만든 뒤 복사한다(record.py가 이렇게 함).
- 자막·말풍선은 짧게: 자막 24자, 말풍선 16자 안팎. 길면 build.py가 경고한다.
- 이 PC에서 check/record는 Playwright가 있는 Python 3.12로, PYTHONHOME·PYTHONPATH를 지우고 실행한다.

## 2026-11-27 실습 사이트 분석 3편에서 겪은 것

- **형식 질문은 두 개로.** 매거진을 고른 사람에게 비율·설명 영상 질문을 따로 묻지 않는다. 형식+비율을 한 질문으로 합쳤다(SKILL.md).
- **매거진 MP4는 record.py가 처리한다.** 예전에는 따로 임시 스크립트를 만들었다. 이제 넘겨 보기 HTML을 넣으면 장면마다 `--hold`초씩 녹화한다.
- **한글 콘솔 인코딩.** 예전에는 check.py가 결과를 출력하다 cp949 오류로 멈췄다. 이제 세 스크립트가 출력을 UTF-8로 고정한다. 다른 파이썬 도구를 쓸 때는 `$env:PYTHONIOENCODING="utf-8"`.
- **장면 넘침은 통과로 숨지 않게.** 모아보기에서 잘려 보이는 장면은 실제로 장면 안 스크롤이다. check.py 경고를 보고 섹션을 나눈다.
- **사이트 화면 캡처.** 에이전트 브라우저 캡처가 여러 번 시간 초과됐다. `scripts/capture.py`를 쓴다. 클릭 뒤 결과가 안 나온 캡처(빈 결과 화면)는 넣지 않는다.
- **PowerShell 변수와 한글.** `"$n일차"`는 `$n일차`라는 변수로 읽혀 빈 문자열이 되고, 두 파일이 같은 이름으로 덮어써졌다. `"${n}일차"`를 쓴다.
- **등록만 한 그림.** images에 넣고 안 쓴 그림은 파일만 무거워진다. build.py가 경고한다.
- **같은 작업의 다음 편.** 형식을 다시 묻지 않고, `meta.series`로 편끼리 잇는다.

## 2026-11-27 Netlify vs Vercel 비교 매거진 인지부하 검토에서 겪은 것

- **점검 통과 ≠ 읽기 쉬움.** 넘침·오류 0이어도 같은 설명 4번 반복, 단위가 다른 결론 숫자, 한 칸에 두 대상, 마지막 장에만 있는 미확인이 남았다. 이제 `build.py`가 `인지부하:` 경고로 잡는다(`references/cognitive-load.md`).
- **색 뜻이 장면마다 뒤집혔다.** lanes에서 청록=Netlify였는데 folders에서 'Vercel 우세' 태그를 청록(a2)으로 칠했다. `meta.sides`를 쓰면 색이 대상에 고정되고 어긋나면 경고한다.
- **결정용 자료는 질문으로 시작.** 맞는/안 맞는 사람 목록 + 숫자 4개보다 `decide` 질문 2~4개가 빨리 읽힌다.
- **표지 그림에 `stage.labels`를 같이 쓰면** hero 위에 알약이 겹친다. hero만 쓸 때는 labels를 비운다.

## 2026-11-27 Visual Intelligence v8 기준 점검에서 겪은 것

- **넘침 0이어도 접근성은 따로.** 진행 막대 점이 높이 5px(손가락으로 못 누름), 뱃지·칩 11px, 강조색 글자 대비 2.7~4.2:1, 흐린 글자 4.2:1이었다. `check.py`가 휴대폰 너비에서 누름 영역 24px·글자 12px·대비 4.5:1·키보드 접근을 본다.
- **강조색은 글자용을 따로.** 배경·선에는 `--accent`, 글자에는 `--accent-ink`(밝은 테마에서 64%로 어둡게). 어두운 상자 안에서는 원래 강조색.
- **질문 고르기는 눌러서 결과가 바뀌게.** 처음엔 모두 보여 주고(MP4·인쇄), 누르면 그 길만 남긴다. 휴대폰에서 '아니오' 칸을 숨기면 누를 수 없으니 작은 버튼으로 남긴다.
- **스킬 파일을 고치면 `selftest.py --browser`.** 고치기 전·후 내용을 시험 자료로 두고 경고가 계속 잡히는지 본다.
- **글자색만 바꿀 때 `color:`를 그대로 찾지 않기.** `border-color:`·`background-color:`까지 바뀐다. `(?<![-\w])color:`로 찾는다.
- **반복 검사는 읽는 글만.** 블록 종류(`steps`), 자세히 창의 고정 제목('왜 하나요?')을 반복으로 세지 않게 `build.py`가 구조용 값을 뺀다.
- **넘겨 보기에서 단계 그림·부탁 글은 높이 제한.** 단계 그림 27vh, 부탁 글 상자 30vh(상자 안 스크롤·복사 버튼). 세로로 긴 휴대폰 캡처가 장면을 넘기던 문제.
- **초보자 예제 장면 나누기(14 → 23섹션).** 한 장면에 단계 5개를 넣으면 1790px 넘쳤다. 장소별로 나누고, 겹치는 결론 숫자·약속 상자는 합쳤다(사실은 빼지 않음).
